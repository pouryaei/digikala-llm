# گراف پرسش‌وپاسخ فروهر و مانیتورینگ

نسخه نهایی Forouhar_100K_Final_Best_Model.zip شامل تمام تغییرات گراف،
داده‌ها و چهار مدل است. دیگر نیازی به نصب بسته به‌روزرسانی جداگانه نیست.

## شروع در PowerShell

بسته نهایی را استخراج کنید و در پوشه Forouhar_Bonus، کنار app.py اجرا کنید:

```powershell
python -m pip install -r requirements.txt
python -X utf8 -m bonus.check_frameworks --require-langgraph
.\RUN_FOROUHAR_FINAL.bat
```

در [Streamlit](http://localhost:8505) روی «آزمایشگاه شواهد و امتیازی →
مسیریاب و مانیتورینگ» بزنید. در بخش «سناریوی آماده برای Demo»، نمونه‌های
زیر آماده‌اند. نمونهٔ آفلاین نیاز به کلید و بودجه ندارد. هنگام مشاهدهٔ مسیر
تیک Result Cache را خاموش نگه دارید تا گره‌ها واقعاً اجرا شوند.

| سناریو | رفتار مورد انتظار بدون مدل |
|---|---|
| آمار مستقیم از داده | پاسخ استخراجی؛ بدون Gateway |
| شاهد مرتبط پیدا نشد | مسیر کمبود شاهد؛ بدون Gateway |
| پوشش ناقص معیارها | نمایش یافته‌های موجود و اعلام موضوع بدون شاهد |
| جمع‌بندی چند معیار با شاهد | پاسخ استخراجی پیش‌فرض؛ مدل فقط با اجازه و کلید |
| درخواست انتخاب محصول | توضیح برای مشخص کردن محصول؛ بدون Gateway |

گراف و جدول زمان، مسیر واقعی اجرا را نشان می‌دهند. اگر موتور
Python fallback نمایش داده شد، آن را اجرای LangGraph معرفی نکنید.

## راه‌اندازی Langfuse روی Windows

1. Docker Desktop را در حالت Linux containers راه بیندازید. در یک پوشهٔ
   جدا از فروهر، [راهنمای رسمی Docker Compose](https://langfuse.com/self-hosting/deployment/docker-compose)
   را تا مرحلهٔ ساخت secrets دنبال کنید. برای دستور bash رسمی می‌توان از
   Git Bash استفاده کرد. فایل .env پوشهٔ Langfuse مخصوص secrets سرویس است،
   نه کلیدهای پروژهٔ فروهر. برای اجرای ارائه روی لپ‌تاپ، پورت‌های منتشرشده
   را محلی نگه دارید؛ پورت را روی اینترنت باز نکنید.
2. در پوشهٔ Langfuse اجرا کنید:

   ```powershell
   docker compose up -d
   docker compose ps
   Invoke-RestMethod http://localhost:3000/api/public/health
   ```

   وقتی health آماده بود، [داشبورد](http://localhost:3000) را باز کنید؛ حساب
   محلی، سازمان و پروژه بسازید و کلیدهای پروژه را از تنظیمات بگیرید.
3. در پوشهٔ فروهر، فایل .env موجود را ویرایش کنید یا اگر ندارد از
   .env.example کپی بگیرید. فقط خطوط زیر را اضافه یا جایگزین کنید:

   ```dotenv
   FOROUHAR_LANGFUSE_ENABLED=1
   LANGFUSE_BASE_URL=http://localhost:3000
   LANGFUSE_PUBLIC_KEY=pk-lf-...
   LANGFUSE_SECRET_KEY=sk-lf-...
   LANGFUSE_TRACING_ENVIRONMENT=forouhar
   ```

   برای این تست QBC13_API_KEY لازم نیست. اگر به جای سرویس محلی از نسخهٔ
   میزبانی‌شده استفاده می‌کنید، همان HTTPS منطقهٔ پروژه را وارد کنید. کلیدها
   را در Git، خروجی قابل اشتراک، یا پرزنت وارد نکنید.
4. از پوشهٔ فروهر ارسال بدون مدل و بررسی دریافت را اجرا کنید:

   ```powershell
   python -X utf8 -m bonus.check_frameworks --require-langgraph --export-langfuse --verify-server
   ```

   server_verified یعنی سرور v4 گره‌های همان Trace را از
   [Observations API v2](https://langfuse.com/faq/all/export-single-trace-or-session)
   برگردانده است. submitted_unverified فقط یعنی SDK عملیات flush را انجام
   داده؛ رسیدِ سرور نیست. اگر آزمایش هنوز تأیید نشد، سلامت سرویس، پروژه و
   کلیدها را بررسی کنید و شناسهٔ Trace را در داشبورد جست‌وجو کنید.
   پس از تغییر .env برنامهٔ Streamlit را دوباره اجرا کنید.

ارسال خارج از برنامه اختیاری است. سؤال، متن نظر، پاسخ و prompt به
Langfuse فرستاده نمی‌شوند؛ فقط متادیتای اجرا مانند علت مسیر، تعداد شواهد،
زمان گره‌ها، وضعیت ساختاری ارجاع و مصرف گزارش‌شده ثبت می‌شود.
مانیتورینگ محلی به Langfuse وابسته نیست.

## نتیجه و دفاع

```powershell
python -X utf8 -m bonus.evaluate_qa_graph
```

گزارش آفلاین: reports/bonus/qa_graph_ab.json. مقایسهٔ ۳۶ مورد روی دادهٔ واقعی
بسته بین RAG فعلی و LangGraph آفلاین انجام شده و خروجی محتوایی و شناسهٔ
شواهد مقایسه شده‌اند. آزمایش سیاست «همیشه مدل برای سؤال قابل پاسخ» در
برابر «مدل فقط برای جمع‌بندی مستند» از پنج سناریو و مدل آزمایشی استفاده
می‌کند. این آزمایش میزان هزینه، کیفیت یا سرعت مدل واقعی را نمی‌سنجد.

اگر کلید گروه و بودجه دارید، برای مقایسهٔ زندهٔ همان پنج مورد (حداکثر هشت
تلاش Gateway در مجموع هر دو مسیر، بدون Cache) صریحاً حالت زنده را اجرا کنید:

```powershell
python -m pip install -r requirements-llm.txt
python -X utf8 -m bonus.evaluate_qa_graph --live --output reports/bonus/qa_graph_live_local.json
```

این خروجی محلی شامل متن پاسخ و شواهد است. هزینه فقط با تعرفهٔ واقعی
FOROUHAR_INPUT_USD_PER_MILLION و FOROUHAR_OUTPUT_USD_PER_MILLION و usage
گزارش‌شده قابل برآورد است. کیفیت و پشتیبانی ادعاها را جداگانه و ترجیحاً
بدون اطلاع داور از نوع مسیر امتیازدهی کنید. اگر Gateway در دسترس نیست،
دموی آفلاین همچنان معتبر است، اما نتیجهٔ هزینه یا کیفیت آنلاین ارائه نکنید.

داستان دفاع: «گراف فقط به‌خاطر اسم ابزار نیست. پاسخ مستقیم و کمبود شاهد
بدون مدل می‌مانند. سؤال چندمعیاره فقط وقتی به مدل می‌رود که شواهد لازم حاضر
باشند. اگر ارجاع یا نقل‌قول پذیرفته نشود، پاسخ اولیه حذف نمی‌شود. این
بررسی ارجاع ساختاری است و درستی معنایی را تضمین نمی‌کند. مانیتورینگ
مشخص می‌کند زمان صرف کدام مرحله شده و آیا سیاست اجرا شده است.»
