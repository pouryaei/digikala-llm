# Digikala LLM · QBC13

پروژهٔ بوت‌کمپ برای جست‌وجوی فارسی محصولات دیجی‌کالا، پاسخ مستند به سؤال دربارهٔ نظرها، تحلیل داده و پیش‌بینی وضعیت پیشنهاد خرید.

## وضعیت فعلی

این مخزن اسکلت روز اول است. هشت مسیر FastAPI با دادهٔ نمونه، تست محلی رابط، سازندهٔ پرسش‌های ارزیابی و پیکربندی Docker را دارد. در پاسخ‌های فعلی API، مقدار `mode` برابر `mock` است. خروجی mock برای هماهنگی رابط‌هاست و پاسخ‌های آن از کاتالوگ واقعی بازیابی نمی‌شوند.

| بخش | وضعیت |
|---|---|
| دادهٔ خام | نسخهٔ ثابت هر دو CSV با SHA-256 تطبیق داده شد. هدرها، کیفیت داده و اتصال محصول و نظر ممیزی شدند. |
| محیط اجرا | Python 3.11 در `btq` و اجرای PyTorch روی CUDA در Windows بررسی شدند. |
| تست محلی | ۱۱ بررسی mock پاس شد. پیش‌بررسی API در حالت dry run صفر درخواست به درگاه داشت. |
| ارزیابی | پیش‌نویس ۲۰ پرسش فارسی از CSVهای واقعی ساخته شد. مرور شواهد و تثبیت معیارها باقی است. |
| Docker | پیکربندی Compose اعتبارسنجی شد. اجرای کانتینر یک بررسی جداگانه است. |
| اتصال API زنده | احراز هویت، پاسخ زنده، latency و تعرفهٔ درگاه هنوز تأیید نشده‌اند. |
| رابط‌ها | هشت مسیر اولیه آمادهٔ مرور تیم‌اند. شِمای دقیق payloadها و رفتار خطا باید با مصرف‌کنندگان هماهنگ شود. |

## اجرای تست محلی

در یک محیط Python 3.11، از ریشهٔ مخزن اجرا کنید. اگر محیط `btq` را دارید، ابتدا آن را با `conda activate btq` فعال کنید.

```powershell
python -m pip install -r requirements-day1.txt
python -m qbc13_day1.check_mock
python -m qbc13_day1.probe
```

خروجی مورد انتظار `PASS: 11 in-process mock checks` و `DRY RUN. Sent requests: 0.` است. نصب وابستگی‌ها ممکن است به مخزن پکیج وصل شود. تست mock و dry run به کلید QBC13 نیاز ندارند.

برای مشاهدهٔ OpenAPI، سرور محلی را اجرا کنید و به [صفحهٔ docs محلی](http://127.0.0.1:8000/docs) بروید.

```powershell
python -m uvicorn qbc13_day1.mock_api:app --host 127.0.0.1 --port 8000
```

پیکربندی Docker Compose را با این فرمان اعتبارسنجی کنید.

```powershell
docker compose -f compose.day1.yml config --quiet
```

## داده و بازتولید پرسش‌های ارزیابی

فایل‌های `digikala-products.csv` و `digikala-comments.csv` را در پوشهٔ محلی `digikala/` قرار دهید. ورودی مرجع، revision ثابت `89c3133b169c8d3793db8834f56f32fee33d9db0` است. CSVهای خام در `.gitignore` تعریف شده‌اند. [دیتاست و نسخهٔ ثابت](https://huggingface.co/datasets/RadeAI/Digikala_comments_products/tree/89c3133b169c8d3793db8834f56f32fee33d9db0)

```powershell
python -m qbc13_day1.build_eval --data-dir .\digikala --output .\eval\day1_queries.jsonl
```

خروجی ۶ پرسش جست‌وجوی محصول، ۱۰ پرسش از نظرها و ۴ پرسش تحلیلی دارد. در صورت وجود فایل خروجی، برای اجرای دوباره مسیر تازه‌ای بدهید. پرسش‌های جست‌وجو هدف شناخته‌شده بر اساس عنوان محصول دارند. برای پاسخ از نظرها، تعلق شاهد به محصول و پشتیبانی آن از پاسخ را مرور کنید. پرسش‌های تحلیلی فعلی تعداد شناسه‌های یکتا را در **فایل خام** هدف می‌گیرند.

## کلید و بودجهٔ API

`.env.example` فقط جای‌خالی `QBC13_API_KEY` را دارد. کلید واقعی را در متغیر محیطی نشست خود قرار دهید و فایل‌های محلی حاوی کلید را بیرون از تاریخچهٔ Git نگه دارید. حالت پیش‌فرض `probe` برآورد محلی است. گزینهٔ `--send` یک درخواست زنده به درگاه پروژه می‌فرستد و باید جداگانه و آگاهانه اجرا شود.

بودجهٔ مبنای گروه **۲ دلار** است. سقف‌های پیشنهادی **۰٫۱۰ دلار برای تست اولیه** و **۰٫۳۰ دلار برای ارزیابی نهایی و دمو** هستند. **۱٫۶۰ دلار** برای نیازهای بعدی کنار گذاشته می‌شود. نرخ عمومی مدل برای برآورد به کار می‌رود. هزینهٔ واقعی را با اطلاعات درگاه و در صورت ارائه با فیلد `usage` ثبت کنید.
